## 4. Architecture

### Server-Side
- **Homepage (`page.tsx`)**
  - Fetches hero slides, categories (with counts), catalog metadata, and first page of products
  - Uses `revalidate = 60` for ISR caching
  - Sanity client uses `useCdn: true` for public reads

### API Routes
- **`/api/products`** (GET)
  - Paginated, server-filtered product loading
  - Query params: `offset`, `limit`, `categoryId`, `search`, `units`, `weights`, `tags`, `priceMin`, `priceMax`
  - Returns: `{ products, total, hasMore, nextOffset }`

- **`/api/place-order`** (POST)
  - Accepts order data, stores in Sanity as text document
  - Accepts optional `orderCode` from client

- **`/api/revalidate`** (POST)
  - Secured by `SANITY_REVALIDATE_SECRET`
  - Calls `revalidatePath("/")` for on-demand cache invalidation
  - Expects secret in `x-sanity-secret` header or `secret` query param

### Client-Side
- **`ShopPageScreen`** — Main shop component
  - Receives `initialProducts`, `totalProductCount`, `pageSize`, `catalogMetadata`, `categories`, `heroSlides`
  - Infinite scroll via `IntersectionObserver` (auto-loads next page)
  - Debounced search (250ms)
  - Server-driven filtering: category, search, weight, tag, unit, price range
  - Stale request protection via request IDs
  - Dedupes products by `_id` when appending pages

- **`CartContext`** — Cart state management
  - `addToCart`, `removeFromCart`, `updateQuantity`
  - Persists to `localStorage`
  - Tracks `totalItems`, `totalPrice`

- **`CartPageScreen`** — Checkout + WhatsApp order flow
  - Client-side order code generation
  - Client-side message building
  - Synchronous WhatsApp deep link (`whatsapp://`) with web fallback
  - Fire-and-forget order storage to backend

## 8. Current Behavior

### Product Loading
1. Homepage SSR fetches: hero, categories (with counts), metadata, first 24 products
2. Browser renders initial page immediately (small payload)
3. As user scrolls, `IntersectionObserver` triggers auto-load of next 24 products
4. Search/filter changes reset offset to 0, fetch new filtered result set from API
5. All filter/search logic is server-driven via GROQ

### Cart
1. Product cards show "Add to Cart" when item qty = 0
2. After adding, card shows `- [qty] +` inline stepper
3. Cart persisted to `localStorage`
4. Cart panel shown in sidebar (desktop) / accessible via header button

### Order Placement
1. Customer fills form on `/cart-page`
2. Clicks "Place Order"
3. Client generates order code + WhatsApp message
4. Opens WhatsApp synchronously (Safari-safe)
5. Order stored in Sanity in background
